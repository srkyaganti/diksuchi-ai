1. **Pick a system** — e.g. "PALM-120 — Operator Handbook"
2. **Ask in your language** — type, or hold-to-talk the mic
3. **Get the answer** — in the same language, warning first
4. **See the diagram** — pulled from the manual, embedded in the reply
5. **Verify the source** — one click opens the PDF at the exact page
6. **Listen back** — play the answer as audio, hands-free

**Speaker notes:**
> Six short steps. The operator picks the system they're working on. They ask their question — typing if they're at a desk, or holding the mic button if their hands are on the equipment. The answer comes back in seconds, in their language, with the safety warning surfaced first. If the manual contains a relevant diagram, it appears inline — they don't go hunting for "Figure 4-7" in the PDF. Every claim in the answer is cited; one click opens the source at the exact page. And if their hands are busy, they can play the whole answer back as audio. The point of walking through this is that every decision in the product is built around the reality that the user is rarely sitting at a desk.

# Slide 7 — Safe by design

**Slide title:** Warnings first. Specs exact. Sources cited.

**On-slide content (three rules):**
1. **Warnings come first** — every WARNING, CAUTION, or NOTE from the source manual is surfaced before the step it applies to. Always.
2. **Specifications are exact** — torque values, tolerances, and clearances are reproduced byte-for-byte. Never rounded. Never paraphrased.
3. **Every claim is cited** — no bare statements. Every answer carries a clickable reference to the exact page of the source document.

> *"A defence-grade assistant cannot afford a confident wrong answer. Safety, not fluency, is the first priority."*

**Speaker notes:**
> Three rules govern every answer the system gives. One — warnings always come before the procedure they apply to, exactly as the manual presents them. The operator never sees a step without seeing the warning that protects them. Two — specifications are exact. If the manual says 27.5 Newton-metres, the answer says 27.5 Newton-metres. No rounding, no approximation, no paraphrase, even when the surrounding sentence is being translated into Hindi. Three — every claim is cited back to the source. The user can verify any answer against the original page with a single click. Together, these three rules turn the assistant from a clever chatbot into something a safety-critical organisation can actually rely on.

**Visual:** A mock chat reply with a yellow ⚠️ WARNING block above the procedure steps, and a citation pill at the bottom.

# Slide 8 — Built for the field, not the cloud

**Slide title:** Runs on a server. Runs on a base. Runs air-gapped.

**On-slide content:**
- **No foreign cloud. No foreign API. No data ever leaves the customer boundary.**
- **Three deployment modes:**
  - **Single-server** — a workstation-class machine with a GPU, enough for a unit.
  - **On-base cluster** — split across hosts for larger sites.
  - **Air-gapped** — fully disconnected, models pre-loaded, no network at all.
- **Multi-tenant inside one deployment** — separate units, teams, and document sets are hard-isolated from each other.

**Speaker notes:**
> Where the product runs is as important as what it does. There is no foreign cloud anywhere in the path, no foreign API in the critical path, and nothing about a query — voice, text, or document — leaves the customer's boundary. We deploy three ways. On a single GPU-equipped server for a small site. In a cluster split across hosts for a larger installation. And fully air-gapped — with no network connectivity at all — for environments that require it. Inside one deployment, separate teams or units can be onboarded as distinct organisations, with their documents and chats hard-isolated from each other at the database level. So one system can serve multiple customers or multiple units without any data crossing.

# Appendix — speaker-prep cheat sheet (not a slide)

**One-liners to keep ready:**
- *"A smart assistant that has read every manual."*
- *"Warnings first. Specs exact. Sources cited."*
- *"Runs on a server. Runs on a base. Runs air-gapped."*
- *"Voice in, voice out, in your language."*

**Numbers to have ready:**
- 14 languages live (English, Hindi, Bengali, Tamil, Telugu, Marathi, Gujarati, Kannada, Malayalam, Punjabi, Assamese, Nepali, Sanskrit, Hebrew).
- Production-grade today; not a prototype.
- Three deployment modes — single-server, cluster, air-gapped.

**Likely questions and short answers:**

- **"How accurate is it?"** — Three things govern accuracy. First, we return whole procedures, not fragments — so the operator never sees step 7 without steps 1 through 6. Second, the system is required to cite every claim back to a specific page, which the user can verify. Third, identifiers like part numbers and torque values are reproduced exactly, never paraphrased, even when the surrounding answer is being translated.
- **"What kinds of manuals can it ingest?"** — PDFs are the workhorse, including scanned and complex-layout PDFs. Structured technical-documentation standards like S1000D are also supported. Tables, diagrams, and warning boxes are all preserved.
- **"What languages are coming next?"** — The current 14 cover the most-asked languages for our deployment contexts. Adding a language is a controlled engineering effort, not a redesign — driven by which customer environment needs it next.
- **"Does it work without internet?"** — Yes. Fully air-gapped deployment is a first-class mode. No external service is required for any part of the user-facing flow.
- **"How does it handle updates to manuals?"** — Each version of a document is ingested as a distinct record. When a manual is revised, the new revision is added and the assistant uses the current revision for new answers; older answers retain a reference to the revision they were generated against.
- **"What hardware does it need?"** — A workstation-class server with a single GPU is sufficient for a unit-scale deployment. Larger sites scale across multiple hosts. The footprint is modest; this does not require a data centre.
